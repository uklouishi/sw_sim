## 待确认

### 🟡 1. 牌库在伤害结算中途用完
- 当前实现：牌库在任何时候变成 0 张都**立即**洗牌重整（结算区里正在结算的伤害卡不参与重整）；重整伤害（牌库顶 1 张放到伤害区）留到下一个规则处理时点，也就是这次伤害处理完之后。
- 需要核对综合规则中“洗牌重整”和“重整伤害”的时点条文。

### 🟡 2. 规则处理的先后顺序
- 当前实现：洗牌重整 → 升级 → 重整伤害 → 败北判定，循环到没有可处理的事项；同一项里回合玩家先处理。
- 双方在同一个规则处理时点都满足败北条件时判平局。
- 需要核对：升级和重整伤害的先后、双方同时升级时谁先选、同时败北是否平局。

### 🟡 3. 结束阶段的顺序
- 当前实现：手牌超过 7 张弃到 7 张 → 名场面区的卡放到休息室 → “直到回合结束为止”的效果结束。

### 🟡 4. 助太刀的能量费用
- 数据里只有 `Backup 2500` 这样的数值，没有费用。当前实现：**等级 1 以上的助太刀费用为 1 能量，等级 0 为 0**，另外要把这张卡从手牌放到休息室；使用条件是这张卡的等级 ≤ 自己的等级。
- 需要和原模拟器生成的文字（如 `Act: BACKUP 2500 Level 2 [(1) Discard this card]`）核对：费用是按等级还是按卡片 `Cost` 字段决定。
- 一次反击步骤只能使用 1 次助太刀（当前实现）。需要核对。
- 反击事件（`Counter`）在 P1 不可使用（没有效果），P3（效果脚本）实现。

### 🟡 5. 侧面攻击的魂减少
- 当前实现：宣告时按对面角色的等级决定，作为这次攻击的修正；之后对面角色离开舞台（例如被风吹弹回手牌）也不改变。
- 魂最低为 0；伤害为 0 时不翻卡、不触发火烧。

### 🟡 6. 正面攻击倒置的角色
- 当前实现：倒置的角色仍占着格子，可以被正面或侧面攻击，对面有倒置角色时不能直接攻击。

### 🟡 7. 判定图示细节
- 判定卡先放到能量区，再处理图示；一张卡有多个图示时按数据顺序逐个处理。
- 魂图示：攻击角色魂 +1 / +2，直到回合结束。攻击角色已离开舞台时不加。
- 风吹：可选对手任意 1 个角色（前列、后列都可以）返回手牌。
- 开机：等级 ≤ 自己等级 +1 的角色，横置放到任意格；格子上原有角色放到休息室。
- 金砖：判定的这张卡从能量区加入手牌，之后可将牌库顶 1 张放到能量区。
- 火烧：攻击伤害被取消时再给予 1 点伤害（这 1 点也可以被取消）；多个火烧图示各给 1 点。
- 特殊图示（Focus、Telescope、Light、Bulb、Peaceful、Aya、ConditionalTelescope）P1 不处理。

### 🟡 8. 再演步骤
- 当前实现：回合玩家先，按格子顺序（前列左 → 后列右）逐个把倒置角色放到休息室，能量 ≥ 3 时询问是否支付 3 能量横置放回原格。
- 综合规则里是由玩家选择处理顺序；P1 没有卡片效果，顺序不影响结果，P3 加入【自】后要改成让玩家选择。

### 🟡 9. 数据：缺省字段
- 约 2.1 万张角色卡的 CardData 里没有 `Soul` 行（例如 SAO/S100-E001），当前按**魂 1**处理；明确写 `Soul 0` 的 13 张保留 0。需要和原模拟器显示核对。
- `Clone X` 卡（265 张，再录 / 异画）在 CardData 里只有一行 `Clone X`。当前实现：没写的字段全部沿用卡号 X，写了的字段以自己为准。完整 cards.json 中只剩 1 张 Clone 找不到对象（不载入）。需要核对 13 张自带部分字段的 Clone 卡（如 `AOT/S50-E013b`）在原模拟器里的表现。
- 还有 3 张角色战力为 0（`AOT/SX04-001`、`ZM/W03-007`、`ZM/W03-009`），待查数据。

### 🟡 10. 猜拳与先后手
- 当前实现：用种子随机决定猜拳胜者，胜者选择先攻或后攻。先攻玩家先换牌。
